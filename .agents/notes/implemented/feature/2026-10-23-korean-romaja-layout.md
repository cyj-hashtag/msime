# Agent Note: 桌面韩语可选罗马字布局与稳定提交边界

Status: implemented

## Problem

现有韩语只提供两套式键位。希望用拉丁拼写输入韩文的桌面用户缺少同一韩语方案内的布局选择。罗马字的多字符元音和 `ng` 还会重解释之前的按键，直接逐键投喂两套式会提前提交无法修复的文字。

## Decision

`scheme = korean` 内提供 `korean.layout`，默认 `dubeolsik`，用户可以在设置中选择 `romaja`。Windows、macOS、Linux 实体键盘支持此布局，显式用 `x` 输入初声 `ㅇ`，退格删除当前拼写的最后一个拉丁按键。`bang` 退格变成 `ban`（반），`gwa` 退格变成 `gw`（구）。

罗马字解析保留来源位置，复用韩文组合规则，只提交后续输入不能改写的完整音节；`hang` 显示 항，继续输入 `ug` 得到 한국。`q/v/z` 等布局外字母保留原样，与当前韩文一起显示在输入位置，不能在已吃键后回放。

共享偏好与宿主能力分开：只有完成接入的桌面会话启用罗马字，旧宿主和移动端默认继续两套式，保留同步的偏好。组字中的布局变更在本次组合结束后生效，Windows 的 Server 与 TSF 自有会话必须保持相同有效布局。保留单音节 Hanja、原方案编号及现有半角标点规则。

键位参考 `rimeinn/rime-mungyeong@34c1b1437824e1e619e7429fb5f461dc7e754939` 的 public domain 码表；不引入 Rime 或 Lua 运行时。

## Alternatives considered

- 逐键转为两套式键流：复用最多、改动最少，但 `gw` 到 `gwa`、`hang` 到 `hangug` 会改写旧解释，已经提交后无法修复。
- 整个单词留到空格：解析和退格较简单，但改变现有逐音节显示与单音节 Hanja 的范围，未提交状态随长输入增长。
- 按韩文字母部件退格：更接近文镜，但需要另一套编辑来源规则；用户批准原始按键退格，保持同一份原始输入可重算。

## Testing

测试保留两套式的 11172 音节往返与既有分配预算。罗马字另穷举 11172 个现代音节的规范拼写，覆盖多字符编码、歧义、稳定提交、来源边界、原始按键退格、布局外字符及长输入。逐键流式结果必须等于整个前缀重新解析，组合所有编码对和延续键，并用固定种子的长输入检查边界。偏好与宿主测试覆盖创建和刷新、移动端回退、会话隔离、组合中切换以及 Hanja。共享设置控件按宿主能力显示，Windows 原生设置使用同一偏好字段。

Windows GNU 工具链上，引擎韩语 54 项、偏好 2 项、宿主边界 6 项、运行时 8 项、设置控件相关 23 项均通过，两套式组字与汉字转换两个 golden 场景也通过。桌面前端构建、Harmony 类型检查和独立 C++ 选项/按键辅助代码验证通过。全仓 quick 的 Rust 检查通过，但门禁整体因本机编码、Bash 和当时的原生配置问题失败。严格 Clippy 存在未改动的基线告警，对已有三类 lint 显式放行后相关 crate 全部目标通过；仓库没有新增豁免。

首轮 CI 发现两处原有测试仍使用新增能力前的预期：共享界面的韩语选项列表，以及 macOS 会话选项的字段数。已同步为两种布局和三项宿主能力，并补充 `korean_romaja` 强制开启、原配置不被修改的断言。相关共享设置测试三个文件共 23 项在本机通过；macOS 原生测试交由 CI 复验，编译与单测不能代替 InputMethodKit 实际输入验收。

随后配置本机 MSVC 2022、Windows SDK 10.0.26100 和固定版本 vcpkg，完整编译 x64 宿主 DLL、Server、TSF 与 WinUI 设置应用；`windows-korean-keys` 的新增罗马字和原有两套式回归通过。实际启动 WinUI，检查默认两套式及已保存罗马字配置的选中状态和说明显示。额外的既有 `windows-korean-hanja-presentation` 在第 107 行超长释义断言失败：4090 字节加两空格及 `/ə/` 恰为 4096 字节，未超过显示函数的上限；相关测试与显示函数均未修改。

本机 Docker 的 Debian 12 隔离桌面中，IBus 1.5.27、Fcitx5 5.0.21 原生宿主和真实 GTK3/X11 编辑框通过四次会话验收：未配置布局时两套式正常，可选罗马字的预编辑、最终文字、退格、布局外字母、紧音、标点、汉字候选、Escape 与失焦写回均正常。Fcitx5 按框架的每上下文规则显式激活新输入框的水杉。保留编辑框及候选界面截图；临时复现脚本与日志位于任务审核材料，不进入源码树。

Windows TSF 在系统应用中的实际键入及 WinUI 点击保存仍未验收，界面自动化工具初始化失败；截图仅证明已保存配置的显示。macOS 没有可用 Mac，未运行 InputMethodKit。Linux 结果限于 GTK3/X11，不覆盖 Wayland、Qt、完整设置应用和跨应用切换。全仓 quick 尚未重新运行到全部通过。

## Consequences

后续按键不能改写已经显示在输入位置的前缀，因此原始按键仅保留仍可编辑的部分；代价是存在歧义时预编辑可暂时包含多个韩文字母。稳定边界同时覆盖编码扩展和 `ng` 上下文，不用固定长度截断。偏好重建沿用宿主已有的空闲门槛；Windows 两侧会话共用能力注入函数，保持布局一致。移动端保存偏好不影响现有键面。原生平台验证必须分别记录，共享测试不能代替实际系统输入验收。
