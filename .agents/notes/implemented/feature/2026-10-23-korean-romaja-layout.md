# Agent Note: 桌面韩语可选罗马字布局与稳定提交边界

Status: implemented

## Problem

现有韩语只提供两套式键位。希望用拉丁拼写输入韩文的桌面用户缺少同一韩语方案内的布局选择。罗马字的多字符元音和 `ng` 还会重解释之前的按键，直接逐键投喂两套式会提前提交无法修复的文字。

## Decision

`scheme = korean` 内提供 `korean.layout`，默认 `dubeolsik`，用户可以在设置中选择 `romaja`。Windows、macOS、Linux 实体键盘支持此布局，显式用 `x` 输入初声 `ㅇ`，退格删除当前拼写的最后一个拉丁按键。`bang` 退格变成 `ban`（반），`gwa` 退格变成 `gw`（구）。

罗马字解析保留来源位置，复用韩文组合规则，只提交后续输入不能改写的完整音节；`hang` 显示 항，继续输入 `ug` 得到 한국。`q/v/z` 等布局外字母保留原样，与当前韩文一起显示在输入位置，不能在已吃键后回放。

共享偏好与宿主能力分开：只有完成接入的桌面会话启用罗马字，旧宿主和移动端默认继续两套式，保留同步的偏好。组字中的布局变更在本次组合结束后生效，Windows 的 Server 与 TSF 自有会话必须保持相同有效布局。保留单音节 Hanja、原方案编号及现有半角标点规则。

键位参考 `rimeinn/rime-mungyeong@34c1b1437824e1e619e7429fb5f461dc7e754939` 的 public domain 码表；不引入 Rime 或 Lua 运行时。

## Alternatives considered

- 逐键转为两套式键流：复用最多、改动最少，但 `gw` 到 `gwa`、`hang` 到 `hangug` 会改写旧解释，已经提交后无法修复。
- 整个单词留到空格：解析和退格较简单，但改变现有逐音节显示与单音节 Hanja 的范围，未提交状态随长输入增长。
- 按韩文字母部件退格：更接近文镜，但需要另一套编辑来源规则；用户批准原始按键退格，保持同一份原始输入可重算。

## Testing

测试保留两套式的 11172 音节往返与既有分配预算。罗马字另穷举 11172 个现代音节的规范拼写，覆盖多字符编码、歧义、稳定提交、来源边界、原始按键退格、布局外字符及长输入。逐键流式结果必须等于整个前缀重新解析，组合所有编码对和延续键，并用固定种子的长输入检查边界。偏好与宿主测试覆盖创建和刷新、移动端回退、会话隔离、组合中切换以及 Hanja。共享设置控件按宿主能力显示，Windows 原生设置使用同一偏好字段。

Windows GNU 工具链上，引擎韩语 54 项、偏好 2 项、宿主边界 6 项、运行时 8 项、设置控件相关 23 项均通过，两套式组字与汉字转换两个 golden 场景也通过。桌面前端构建、Harmony 类型检查和独立 C++ 选项/按键辅助代码验证通过。全仓 quick 的 Rust 检查通过，但门禁整体因本机编码、Bash 和当时的原生配置问题失败。严格 Clippy 存在未改动的基线告警，对已有三类 lint 显式放行后相关 crate 全部目标通过；仓库没有新增豁免。

首轮 CI 发现两处原有测试仍使用新增能力前的预期：共享界面的韩语选项列表，以及 macOS 会话选项的字段数。已同步为两种布局和三项宿主能力，并补充 `korean_romaja` 强制开启、原配置不被修改的断言。相关共享设置测试三个文件共 23 项在本机通过；macOS 原生测试交由 CI 复验，编译与单测不能代替 InputMethodKit 实际输入验收。

随后配置本机 MSVC 2022、Windows SDK 10.0.26100 和固定版本 vcpkg，完整编译 x64 宿主 DLL、Server、TSF 与 WinUI 设置应用；`windows-korean-keys` 的新增罗马字和原有两套式回归通过。既有 `windows-korean-hanja-presentation` 的超长释义样例实际恰为 4096 字节；审查后改为分别检查 4096 字节保留读音、4097 字节省略读音，两项均通过，没有修改生产显示上限。

本机 Docker 的 Debian 12 隔离桌面中，IBus 1.5.27、Fcitx5 5.0.21 原生宿主和真实 GTK3/X11 编辑框通过四次会话验收：未配置布局时两套式正常，可选罗马字的预编辑、最终文字、退格、布局外字母、紧音、标点、汉字候选、Escape 与失焦写回均正常。Fcitx5 按框架的每上下文规则显式激活新输入框的水杉。保留编辑框及候选界面截图；临时复现脚本与日志位于任务审核材料，不进入源码树。

审查后在本机临时注册 full 测试版，与原有 C++ 版使用不同身份。WinUI 实际点击保存两套式和罗马字，偏好修订递增；已注册的生产 TSF、Server 和真实文本存储完成两套式 `gksrnr`、罗马字 `hang` 延续为 `hangug`、Return、`bang` 按原始键退格、Escape、右 Ctrl 打开汉字候选及数字选择 `韓`。切换输入框后，新框独立组字、原框文字保留；但实验编辑器的候选定位仍不稳定，不能记为整套界面通过。首轮记事本截图报 `IGraphicsCaptureItemInterop.CreateForMonitor 0x80070057`，没有输入；第二轮截图恢复，实际按键 `hangug` 写入 `한국`，WinUI 切回两套式后 `gk` 写入 `하`，保存的 UTF-8 文件逐码位核对通过。Return 提交后同时换行，符合 TSF 的 CommitAndPass。首次激活时曾观察到 `gk` 写入分离的 `ㅎㅏ`，后续切换布局复测未复现，保留为待查问题；截图中的缺字方框也不能算界面通过。会话输入源已恢复，两次临时注册均已注销，测试进程已停止，原有 C++ 注册保留。系统全应用覆盖仍有缺口；Linux 结果限于 GTK3/X11，不覆盖 Wayland、Qt、完整设置应用和跨应用切换。

审查后增加 `korean-romaja-controller` 原生集成入口：经生产 `prepareSession` 声明能力并创建真实 Rust 会话，再由 `handleEvent:client:` 写入 AppKit 的 `NSTextView`，检查两套式缺省、罗马字的 `ng` 延续、按原始键退格、布局外字母、紧音、标点、汉字候选、Return 传递和失焦文档归属。单进程夹具只隔离框架基类的最后一次失焦 IPC，同时检查生产控制器确实调用它。此入口已在 macOS 15 arm64 CI 通过，同次原生 CTest 共 181 项通过；x86_64 作业跳过构建，不能算作 Intel 验证。

另增加独立 `korean-system-input-acceptance`：不导入控制器或宿主库，向自己的原生编辑框投递系统键盘事件，必须经已安装输入源的 IMK 连接写入文档。程序核对安装路径、输入源和实际文字，记录 marked 状态、逐项结果与未满足的前提，退出时恢复先前输入源；不请求或修改系统权限。CI 只编译并运行前提探测。`b139d508` 的 macOS 15 arm64 原生测试为 181/181，上传的 JSON 明确报告 `event_posting_allowed: false`、`system_input_executed: false`，当前输入源为系统 US 布局。托管 runner 不具备系统按键投递权限，用户也没有可用 Mac，完整系统输入入口尚未执行，不能把控制器测试通过等同于系统验收。

在固定 `develop` 提交 `d4d2f5ccfec7d1f2c0229beb4ef9455ab2626543` 的独立副本与当前分支使用同一工具链成对复跑 15 项检查：十一项发布、打包或目录脚本在两边同样失败，两个 Windows C++ 检查直接执行在两边通过；符号表与语音目录在 LF 基线通过、CRLF 工作副本失败，恢复 Git 中原有 LF 字节后再验证，不改逻辑或增加 known-failures。Harmony 比较先装齐基线依赖，避免将跳过误记成通过。Bash 的进程选择与子进程编码失败保留原始日志和测试源码哈希。合并新 `develop` 前的一次全仓 quick 已运行到结束并失败，Rust 工作区、笔记和 pipe-only 构建通过。

再合并 `develop` 提交 `4fcc62e34a1cf6441df8c0975c9d2916a616a35c` 后，修正三处既有偏好测试夹具编译错误，韩语相关四个 crate 共 70 项通过，触屏布局与混输偏好的两项夹具另行通过。MSVC 全量构建暴露多项 TSF 测试未声明 UTF-8 源码，改为该目录统一启用 `/utf-8`；Caps Lock 的源码接线检查改用文本读取 CRLF，独立构建和执行通过。macOS 合并后的 CTest 中韩语控制器仍通过，唯一失败为新增 Android 文本拖拽手势缺少平台说明；核实只由 Android 原生键面消费后，按覆盖门禁的既有规则补记 macOS 不适用理由，本机覆盖检查通过。CI 另保存系统输入前提探测，即使其他原生测试失败也能检查托管 runner 的实际条件。

继续构建发现 Windows 顶层测试和演示也包含同类 UTF-8 源码，因此在平台 CMake 入口统一声明编码，保留 TSF 独立配置的编码声明。帧类型范围的四项常量比较改用 `static_assert`，消除 MSVC C4127，不关闭 `/WX` 或放宽断言。测试注册与构建同时发生曾导致已加载 DLL 的 LNK1168；注销后将旧 DLL 移出产物路径，再复用原构建目录。这类文件占用与编码问题分别记录，不视作韩语功能已通过。

## Consequences

后续按键不能改写已经显示在输入位置的前缀，因此原始按键仅保留仍可编辑的部分；代价是存在歧义时预编辑可暂时包含多个韩文字母。稳定边界同时覆盖编码扩展和 `ng` 上下文，不用固定长度截断。偏好重建沿用宿主已有的空闲门槛；Windows 两侧会话共用能力注入函数，保持布局一致。移动端保存偏好不影响现有键面。原生平台验证必须分别记录，共享测试不能代替实际系统输入验收。
